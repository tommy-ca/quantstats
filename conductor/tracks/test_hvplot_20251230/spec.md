# Spec: Unit tests and E2E tests for hvPlot migrations

## Overview
This track aims to establish a robust testing framework for the hvPlot migration. The focus is specifically on ensuring that the newly implemented interactive plots correctly integrate into the final HTML reports generated by QuantStats.

## Functional Requirements
- **Unit Tests:** Verify individual plot functions return valid hvPlot/HoloViews objects when provided with live market data.
- **E2E Tests:** Generate full HTML reports using live data and verify the output.
- **DOM Verification:** E2E tests must parse the generated HTML and confirm the presence of:
    - Bokeh-specific `<div>` elements for plot containers.
    - Necessary `<script>` tags for Bokeh and HoloViews runtimes.
    - JSON payloads containing the plot data/configuration.

## Non-Functional Requirements
- **Reliability:** Tests must handle potential network issues when fetching live data via `yfinance`.
- **Maintainability:** Use standard Python testing libraries (e.g., `pytest`, `beautifulsoup4` for DOM parsing).

## Acceptance Criteria
- [ ] Test suite successfully fetches live data for a sample ticker (e.g., "AAPL").
- [ ] Tests confirm that `qs.reports.html()` produces a file containing valid interactive plot markers.
- [ ] No regression in report generation for standard metrics.

## Out of Scope
- Visual regression testing (screenshot comparison).
- Performance benchmarking of the plotting backend.
